### Autonomous run

1. State a checkable done condition and the user's scope, budget, and explicit checkpoints.
2. Work in this turn while useful progress is possible. Use tools and permitted native subagents to investigate and implement. For a user-requested later continuation or recurring monitor, use the available Codex automation tool. Do not create a schedule just because a task is long.
3. Iterate through a hypothesis, focused change, and observation of the real result. Verify each meaningful unit before the next. Preserve unrelated work when reverting an unsuccessful experiment.
4. Fix blockers within the authorized scope. Record adjacent discoveries as local follow-ups unless the user authorized that extra work. A long-running instruction does not grant permission to send messages, deploy, merge, or delete user data.
5. Keep a decision trail with show-me-your-work when the user will review the work later. Record evidence, remaining gaps, and the current stopping condition.
6. Stop when the done condition is met, the user asks to stop, or a real dependency or host limit prevents progress. Report the actual state and a concrete handoff when blocked; do not loosen the criterion or claim a later wake that was never scheduled.

Reply with the result against the done condition, verification, useful iterations, and any remaining boundary.
